Question 1: Least Squares and Matrix Calculations

Problem

Set the random seed to 43201. Generate n=100 observations with p=5 predictors according to:

  • x_ij ~ iid N(0,1) for i=1,...,100 and j=1,...,5
  • ε_i ~ iid N(0, 0.7²)
  • β = (3, 1.4, -0.9, 0.7, 0, 1.1)ᵀ
  • y = Xβ + ε

(a) Generate the data and report dimensions, rank of X, and compare LS estimates to true coefficients.

(b) Calculate fitted values, residual vector, and training RMSE.

(c) Report ||XᵀR||∞ and explain its significance.

Solution

Key Results:

Statistic Value Description
Dimensions of X 100 × 6 100 observations, 1 intercept + 5 predictors
Rank of X 6 Full rank (expected for Gaussian design)
Training RMSE ≈ 0.67 Close to true error SD of 0.7
||XᵀR||∞ ≈ 10⁻¹⁴ Machine precision (near zero)

Part (a): Least Squares Estimation

True Coefficients: (3.0, 1.4, -0.9, 0.7, 0.0, 1.1)

Estimated Coefficients: (3.006, 1.417, -0.888, 0.795, 0.048, 1.132)

The estimates are close to the true values, with the coefficient of x₄ near zero as expected. The small differences reflect the stochastic nature of one data realization.

Method: We use a numerically stable QR or SVD-based least-squares routine (like lm.fit or np.linalg.lstsq) rather than explicitly computing (XᵀX)⁻¹ to avoid amplifying numerical errors.

Part (b): Fitted Values and RMSE

Once we obtain β̂, the fitted values are:

ŷ = Xβ̂

The residual vector r = y - ŷ has a training RMSE of approximately 0.67, which is consistent with the true noise standard deviation of 0.7.

Part (c): Orthogonality and Residuals

The value ||XᵀR||∞ ≈ 10⁻¹⁴ is essentially zero (at machine precision). This is expected because:

  • At the least-squares minimizer, ∇L(β) = -2Xᵀ(y - Xβ) = -2XᵀR = 0
  • The residual vector is orthogonal to all columns of X
  • This includes the intercept column, so Σrᵢ ≈ 0 (residuals sum to zero)
  • The tiny non-zero value reflects only floating-point arithmetic errors

Question 2: Gaussian Likelihood for Linear Regression

Problem

Using data from Q1, suppose Y|X ~ N(Xβ, σ²I). The log-likelihood is:

ℓ(β, σ²) = -(n/2)log(2πσ²) - (1/2σ²)||y - Xβ||²

(a) Explain why maximizing over β is equivalent to minimizing RSS and what this implies.

(b) Derive the MLE of σ² and compare with the unbiased estimate.

(c) Plot the likelihood profile for the x₂ coefficient.

Solution

Part (a): Equivalence of MLE and Least Squares

For fixed σ², the log-likelihood becomes:

ℓ(β, σ²) = -n/2·log(2πσ²) - 1/(2σ²)·||y - Xβ||²

The first term doesn't depend on β. Since -1/(2σ²) < 0, maximizing ℓ(β, σ²) over β is equivalent to minimizing ||y - Xβ||² (the residual sum of squares).

Implication: The MLE of β equals the least-squares estimate β̂, linking likelihood and classical regression.

Part (b): MLE of Variance

To find σ²_MLE, differentiate with respect to σ²:

∂ℓ/∂σ² = -n/(2σ²) + RSS/(2(σ²)²) = 0

Solving: σ̂²_MLE = RSS/n

Estimator Formula Denominator Value
MLE RSS/n n = 100 ≈ 0.4575
Unbiased RSS/(n-p) n - p = 94 ≈ 0.4867

Why different denominators?

  • MLE divides by n because it directly maximizes the likelihood
  • Unbiased divides by n-p (Bessel correction) because p parameters were estimated
  • Under the Gaussian linear model: E[RSS] = (n-p)σ²
  • The unbiased estimator accounts for this degrees-of-freedom loss

Part (c): Likelihood Profile

We plot ℓ(β̂ + t·e_{x₂}, σ̂²_MLE) where e_{x₂} = (0,0,1,0,0,0)ᵀ varies the x₂ coefficient while holding others fixed.

Result: The maximum occurs at t = 0 (the least-squares estimate β̂₂).

Why? Since x₂ is orthogonal to the residuals (from Q1c), any deviation from β̂₂ increases the RSS and decreases the log-likelihood. This confirms that least-squares optimization is equivalent to profile likelihood maximization.

Question 3: Starting Values in Nonconvex Optimization

Problem

Consider f(x) = exp(1.5x) - 3(x+6)² - 0.05x³ with derivative f'(x) = 1.5exp(1.5x) - 6(x+6) - 0.15x².

(a) Plot f(x) over [-40, 7] and describe key features.

(b) Minimize f using BFGS from x₀ = -15 and x₀ = 0. Report final x, f(x), |f'(x)|, and convergence.

(c) Explain convergence to different minima and what's needed to claim global optimality.

Solution

Part (a): Function Characteristics

The plot reveals:

  • Multiple local minima: Two distinct basins of attraction separated by a local maximum
  • Left minimum: Deeper; occurs around x ≈ -32.6
  • Right minimum: Shallower; occurs around x ≈ 2.3
  • Steep rise: The exponential term dominates for large positive x
  • Nonconvexity: Gradient-based optimization is not guaranteed to find the global minimum

Part (b): BFGS Results

Starting Point Final x f(x) |f'(x)| Converged
x₀ = -15 -32.649 -390.386 ≈ 10⁻⁸ Yes
x₀ = 0 2.350 -175.863 ≈ 10⁻⁸ Yes

Both runs report convergence (small gradients), but they found different local minima. The left starting point finds the deeper minimum.

Part (c): Global Optimization Analysis

Why different minima?

  • BFGS is a local optimization method using only gradient information
  • Different starting points fall into different basins of attraction
  • Once in a basin, BFGS converges to that local minimum
  • The local maximum acts as a barrier between basins

Which gives the lower objective? The run starting at x₀ = -15 (f ≈ -390.4 vs. -175.9)

Evidence needed for global minimum:

  1. Analyze limiting behavior: f(x) as x → ±∞
  2. Find all roots of f'(x) (all stationary points)
  3. Evaluate f(x) at every stationary point and compare
  4. Use multiple random starting points and verify convergence to the same solution
  5. Grid search: Densely evaluate f over the domain (as shown in plots)
  6. Formal verification requires proving no other region was missed

Question 4: Nearly Collinear Predictors

Problem

Continue with X and y from Q1. Set seed to 43202, generate u ~ N(0,1), and define:

  • x₆ = x₁ + 10⁻⁴u
  • X₊ = [X | x₆]
  • y* = y + 10⁻³u

(a) Fit y with X and X₊. Report condition numbers, RMSE, and coefficients of x₁ and x₆ for X₊.

(b) Fit y* with X₊. Report coefficient changes and compare fitted values.

(c) Use the identity y* - y = 10(x₆ - x₁) to explain why coefficients change drastically but fitted values don't.

Solution

Part (a): Impact of Collinearity

Design Matrix Condition Number Training RMSE
X (original) ≈ 1.5 ≈ 0.679
X₊ (augmented) ≈ 2×10⁴ ≈ 0.679

The condition number increases dramatically (from 1.5 to 20,000), indicating severe collinearity. However, RMSE stays essentially the same because fitted values depend on the space spanned by columns, not individual coefficients.

Coefficients for X₊ fit to y:

  • β̂₁ ≈ 351.7 (highly unstable)
  • β̂₆ ≈ -350.3 (highly unstable)
  • Sum ≈ 1.4 (stable; close to original x₁ coefficient)

Part (b): Sensitivity to Perturbation

When fitting y* instead of y:

  • Δβ̂₁ ≈ -10 (coefficient of x₁ decreases by 10)
  • Δβ̂₆ ≈ +10 (coefficient of x₆ increases by 10)
  • These large changes cancel out in predictions

Fitted value comparison:

  • RMSE of differences: ≈ 0.001
  • Maximum absolute difference: ≈ 0.003

Despite the coefficient changes being ~10 times larger, fitted values barely change.

Part (c): Why Coefficients Change but Predictions Don't

The key identity is: y* - y = 10⁻³u = 10(10⁻⁴u) = 10(x₆ - x₁)

This means the response perturbation can be exactly reproduced by:

  • Decreasing the x₁ coefficient by 10
  • Increasing the x₆ coefficient by 10

The net contribution to fitted values is: Δŷ = 10(x₆ - x₁) = 10⁻³u ≈ 0.001

Key Insight: When predictors are nearly collinear:

  • Predictions are stable: The data identify the subspace well
  • Coefficients are unstable: Individual effects are not well-determined
  • Only combined effects matter: Β₁·x₁ + β₆·x₆ is identifiable, but β₁ and β₆ separately are not
  • Interpretation is dangerous: Small data perturbations cause huge coefficient swings

Question 6: Fitbit Data and Selection Bias

Problem

Patten et al. (2026) report 39M Fitbit records from 59K participants in the All of Us program. Participants entered via BYOD (bring your own) or WEAR (provided device).

Key statistics: BYOD vs. WEAR

  • White: 77.3% vs. 55.1%
  • Income -25K: 6.1% vs. 15.2%
  • Median daily steps: 6,867 vs. 5,797

(a) Are 39M records independent? What causes unequal contribution?

(b) Does BYOD's higher step count show causation? Alternative explanations?

(c) How do participant and day selection create bias?

Solution

Part (a): Independence and Weighting

Are the records independent? NO.
  • 39M records come from ~59K participants → ~660 records per person average
  • Multiple days from the same person are correlated
  • Reasons: Health status, employment, habits, weather all persist over time
  • Standard analysis must account for participant-level clustering

What causes unequal contribution per participant?

  • Increases records: Long enrollment, consistent use, good sync, technical access
  • Decreases records: Illness, travel, device issues, privacy concerns, low motivation

Unequal weighting problem:

  • Averaging all 39M days gives more weight to people with more recorded days
  • If records/person correlates with activity → systematic bias
  • Example: Active people may maintain wearables better → more days recorded
  • Naive average would over-represent high-activity participants

Part (b): BYOD vs. WEAR Comparison

Does BYOD's higher step count show causation? NO.

The observed difference: 6,867 (BYOD) vs. 5,797 (WEAR) = 1,070 more steps (18% higher)

Why this is NOT causal:

  • NOT a randomized experiment → no causation can be inferred
  • Groups differ in how they enrolled, not just device ownership
  • BYOD: Self-selected (already bought a Fitbit)
  • WEAR: Program-invited (may differ in motivation, health awareness)

Evidence of selection differences:

  • Race: 77.3% White (BYOD) vs. 55.1% White (WEAR)
  • Income: 6.1% earn -25K (BYOD) vs. 15.2% (WEAR)
  • These demographic differences show the groups are fundamentally different

More plausible explanations than causation:

  1. Selection bias: People who own Fitbits are already health-conscious and more active
  2. Socioeconomic status: BYOD participants are wealthier (higher % White, lower poverty), possibly more active
  3. Motivation & access: BYOD users self-selected for wearables; WEAR users were invited (may have lower tech interest)
  4. Retention: BYOD users have sunk costs (bought the device); WEAR users received free device (might drop out easily)
  5. Baseline activity: Before Fitbit ownership, BYOD and WEAR may have had different activity levels

Part (c): Selection Bias from Participants and Days

Target population: Mean of participant-specific average daily steps among US adults (each person weighted equally).

Selection happens at FIVE stages:

  1. Enrollment in All of Us:
    • Voluntary participation
    • May differ from US in: health interest, income, education, geography, demographics
  2. Enrollment route choice (BYOD vs. WEAR):
    • BYOD: Must already own Fitbit (money, tech interest)
    • WEAR: Invited by program (selection by researchers)
  3. Data-sharing consent:
    • Not everyone agrees to share wearables data
    • Privacy concerns differ by demographic group
  4. Technical connection & setup:
    • Requires login, authentication, device sync
    • Higher tech literacy among successful connectors
  5. Sustained device use & valid records:
    • Requires continued motivation and access
    • Illness, travel, device failure reduce days recorded
    • People with stable routines contribute more days

Why the naive average of 39M records fails:

Problem 1: Unequal participant weighting
  • Average gives more weight to people with more recorded days
  • If recording correlates with activity → biased estimate
Problem 2: Selected participant population
  • Observed participants ≠ random US adults
  • Self-selected through multiple stages
  • Likely: more health-conscious, tech-savvy, affluent, healthier
  • This population's mean activity ≠ US adult mean activity
Problem 3: Selected observation days
  • Even among enrolled participants, healthy/active people record more days
  • Sick/disabled people record fewer days
  • This selection by day correlates with step count

Conclusion: Large datasets with selection bias still produce biased estimates. The 39 million records do not guarantee accuracy when the data come from a selected population.
